# Screenshots

One row per picture in `imgs/`: what it shows, and what takes it. Before this existed the commands were gone the moment each shot was taken, so a fault common to all of them — a black strip round two dozen of them, a vault list belonging to one machine, a close cross on every tab — could not be fixed as a batch. See [Building](02-building.md#documentation-screenshots) for the script itself.

## How a picture is taken

```
pwsh scripts/capture-screenshot.ps1 -Doc <file> -Out shot.bmp [flags]
just squeeze-png shot.bmp imgs/<name>.png --palette
```

**A batch is taken against a copy nobody can see.** A run written that way launches its own copy, puts it at 40,40 and brings it to the front, and parks the real pointer before every shot — fine for one picture and intolerable for forty, because each one takes the keyboard off whatever the owner is typing in. So a whole-set retake launches one copy per picture with `scripts/probe-launch.ps1 -Work shot`, which stands it off every monitor, and photographs it with `-Attach -ProbePid <pid>`: the pointer steps go into the page through the app's own gesture ask, and the driver skips both the foreground grab and the pointer park where the window is on no monitor. Two things follow from that. The launcher is called straight rather than through `scripts/probe.mjs`, because that wrapper writes `.tmp/probe-copy.json`, the one pointer both sessions in this checkout share, and a probe the other session launches between the write and the read is the copy every later step then drives. And the gesture ask is addressed by account name — `USERNAME` set to the probe's, with `LEAFTEXT_ASK_ACCOUNT_ONLY` — for the same reason.

**The profile flags do not reach an attached run**, so a batch writes the same three things by hand into `%TEMP%\leaftext-probe-shot`: `roaming yanallen\leaftext\config\settings.json` (the window size, the theme, the padlocks, the graph size, whether the pane is open), `recent-files.json`, and a copy of a `manifest.db` the app built once, with `scripts/shot-add-vault.mjs` writing the vaults into it. `hints_seen` in that settings file holds every name the front end registers with `registerHint`, read out of `src/assets/shell/` rather than written down: the two launch counters only quiet the hint a launch schedules, and one whose target appears later comes up anyway — which is how a vault bubble came to stand over the file list in a picture of a delete.

**The keyboard is the one thing the gesture ask does not carry**, so a `type:` step is refused against an unseen copy and a picture of something typed is made with a line of JavaScript in the page instead. The line rides over as base64 — `eval(atob('…'))` — because Windows PowerShell hands a native command its arguments without escaping the quotes inside them, and a line carrying spaces and brackets arrives split.

**A whole-set retake is about forty launches**, one per picture, each waiting for its page to settle. There is no faster shape while a picture needs its own profile: two pictures cannot share a copy without the second carrying the first one's tabs.

Pictures made from two shots stay PNGs from the capture through the published file. `just compose-shots vertical <out.png> <left.png> <right.png>` keeps each half; `diagonal` puts the first shot at the upper left and the second at the lower right; `grid <out.png> <columns> <shots...>` fills a preview sheet left to right.

Seven things about it are worth knowing before a retake:

- **The picture is the app's own rectangle.** Two frames are cut off it: the window's invisible resize border, and the band the app holds itself off the window by so its shadow has room. Both photograph as pure black, which the app draws nowhere, and a shot at the pinned `-Width 1000 -Height 799` comes back 1440x1166 on a 1.5-scaling display. Pointer steps are offset the same way, so a coordinate is a pixel in the picture — measure the next click off the last shot, and measure a `-Crop` off it too.
- **Nothing is hovered unless a step asks for it.** The pointer is parked off the window before the steps run, because the capture draws what the pointer is over and never the pointer itself — so a control that only appears under one photographs as a control that is simply there.
- **The first-run bubble is off.** The profile is new every run, so without that every picture with the library open would carry one floating over the control it points at.
- **The profile starts empty every run.** Settings, recent files and the vault registry are all written from nothing, and `%USERPROFILE%` with the three `OneDrive` variables point at a folder with no sync client under it. So a shot never shows anything belonging to the machine it was taken on, and a batch never carries one picture's state into the next. One folder is made under that home: an empty `Desktop`, which is where Windows opens a save window and which it errors on when it is missing. It is not a name the cloud lookup asks for, so it registers no vault.
- **A cloud vault is staged, not borrowed.** Creating `%TEMP%\leaftext-shot\home\Dropbox` before a run is enough: the app finds it the way it finds a real one and registers it as a vault wearing a cloud. A folder of real documents can be junctioned in under it, which is what `<vault>` below is.
- **Several vaults need `-Command`, not `-File`.** Through `-File` an array collapses into one comma-joined string and registers as a single vault with a wrong path. `powershell -Command "& '<script>' -Vault @('a','b') …"` passes them properly. Several steps have the same trouble: pass them as one `-Steps 'click:1,2 wait:900'` string rather than as a `-Do` array.
- **The floating toolbar moves with the page.** Its buttons sit at different coordinates with the library pane open and shut, so a step aimed at one is measured off a shot with the same pane state. At the pinned size with the pane shut the three view buttons are at `667,1111`, `715,1111` and `762,1111`; with it open they are at `847`, `895` and `942` on the same row.
- **A press on a view button leaves the tray hanging out.** The view's own tools ride in a tray behind the bar that comes out while the pointer rests on the active button, so a run whose last step is a press there photographs the tray over the page. End with a `move:` somewhere in the document to park it — and where the press landed *inside* the tray, end with a `click:` instead, because focus holds it out however far the pointer goes.

`<vault>` in the rows below is `%TEMP%\leaftext-probe-shot\home\Dropbox\lower-weir`, a junction to `../docs/tests/vault`, so it registers as a vault wearing a cloud. That folder is in this repository — a gauging station's handbook, its survey method, and twenty-two documents linking to each other — so every picture below can be taken again from what the checkout already holds, and the names in them are that folder's. `<notes>` is `%TEMP%\leaftext-probe-shot\home\notes`, a junction to `../docs/tests/notes`: six pages, a `data` folder and a `diagrams` folder, where `04-margins.md` links to `05-anthology.md`, a file deliberately not made, which is what draws the wavy underline. `<scratch>` is `%TEMP%\leaftext-probe-shot\home\scratch-weir`, a **copy** of `../docs/tests/vault` rather than a junction, because the two delete pictures really do delete the file they name and a junction would take a checked-in document with it. It sits outside `Dropbox` on purpose: a second folder there registers a second cloud vault, and the pane then draws its add-your-notes panel above the file list and pushes every row a shot aims at down the pane.
